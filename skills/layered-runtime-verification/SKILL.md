# 网页应用的分层验证

## 适用条件

适用于前端迁移、多入口共用规则、有状态交互流程，以及“页面能打开但流程或内容可能不完整”的本地应用。输入为获准测试的应用、版本、测试数据、关键路径和验收规则；输出为验证矩阵、逐项结果及失败证据。此 skill 是执行说明，不附带浏览器驱动或通用测试器。实际操作浏览器时加载宿主相应技能。

## 依赖与参数

使用项目已有的测试运行器及浏览器工具；直接连接 CDP 时需要支持该协议的浏览器和客户端。将项目根目录、运行时路径、目标 URL、允许的 origin/路径、CDP 地址、测试账号环境变量、用例矩阵、随机种子、超时、最大步骤数、输出目录配置化。测试账号和会话只通过本地受控配置提供，报告不保存凭据、完整会话或真实用户数据。

## 执行步骤

1. **固定对象与覆盖矩阵**：记录提交、工作树状态、实际服务 URL、构建版本和数据摘要。逐行列出“入口 × 场景 × 预期结果 × 验证层级”。没有执行的行记未运行；可选依赖缺失记跳过及影响，不能汇总为全部通过。核对远程同步时先更新引用并检查 upstream；脏工作树单列报告，不以一个 OK 掩盖。
2. **先做静态检查与单元测试**：检查共享模块引用、加载顺序和导出接口，运行对应规则测试。页面标题或表名的正则比较只能证明被匹配片段的结构覆盖；检查空匹配、重复键、双向差异和归一化碰撞。需要行为一致时，用同一合成输入比较稳定字段和结果，不能用标题子串匹配替代。
3. **绑定正确页面**：连接指定 CDP 地址后，按配置的 origin、路径或明确 target ID 选择测试页。没有唯一匹配就报告配置问题，不回退任意第一个页面。记录导航后实际 URL 和页面标识；需要新标签页时只创建并操作本次测试拥有的页。
4. **使驱动有界失败**：连接、命令、等待状态及整套流程各设超时；CDP 响应按消息 ID 配对，协议错误及 Runtime.evaluate 的 exceptionDetails 均作为失败。连接关闭时拒绝所有未完成请求；在 finally 中关闭本次连接并清理本次资源。优先等明确状态，固定延时只能作为有限退避；达到最大步骤数仍未到达目标状态即失败。
5. **验证冒烟路径**：用隔离账号和合成数据完成加载、关键输入、一次核心操作与结果展示。记录页面运行时异常、必要资源加载失败和关键控件断言；日志监听失败也要报告。控件存在、可点击和产生正确业务结果分开检查。
6. **验证完整流程和多入口一致性**：重置本次测试数据，按矩阵运行起点、中间状态和终点。跨入口使用同一份合成输入，对齐稳定 ID、字段、数量和导出内容。服务可达不代表前端挂载成功，内部状态正确不代表 DOM 展示或下载结果正确。
7. **把质量规则写成硬断言**：按应用配置校验空内容、选项数量、正文长度、占位文本、非数值残留、终点必需区块及出现次数。若要求两类交互都出现，分别断言两类计数大于零；只打印计数不算验收。阈值来自产品要求，不能沿用源业务的固定数字。
8. **确认实际覆盖**：报告实际运行的唯一场景组合、种子、步骤和结果。重复同四组用例八次仍只有四个唯一组合。随机流程保留可复现种子或轨迹；未触发的分支列为未覆盖，不能根据文件头注释推定覆盖。
9. **汇总并设发布门槛**：每项记录命令或操作、版本、通过/失败/跳过/未运行、证据和局限。必需项失败或未运行时不能称完整验收通过。批处理汇总所有失败并返回非零状态；截图仅作为辅助证据，不能代替内容和状态断言。运行日志与截图先脱敏，再按交付清单保存。

## 验收标准

- 验证对象与实际页面绑定明确，参数不含个人硬编码路径。
- 每个宣称已覆盖的场景都有实际执行记录和断言；统计值与断言条件分别可核对。
- 静态结构、单元行为、运行时展示、完整流程及人工视觉检查分别报告。
- 超时、页面不匹配、协议错误、脚本异常和断言失败均产生可诊断失败；资源得到清理。
- 最终报告只声称实际完成的层级，列明未覆盖项和发布门槛。

## 提炼来源与已有能力

本流程来自工作区两个应用中的自有验证脚本，未复制应用、页面文案、账号或测试数据。可按以下相对路径在自己的源工作区复核；这些路径不是本仓库附带的文件，也不是安装依赖。

- `amazon-ppc-keyword-optimizer/tools/health_check.js:9–18,34–61`：逐项聚合检查、测试套件、结构核对和 CDP 冒烟，按失败数量退出。
- `amazon-ppc-keyword-optimizer/tools/ui_parity.js:23–46`：通过正则提取表格标题，单向比较并允许子串匹配；它不证明字段、排序或业务行为一致。
- `amazon-ppc-keyword-optimizer/tools/react_smoke.js:13–29,59–85`：命令超时、运行时日志监听及 DOM 断言的实现示例；现有页面选择仍取第一个 page，求值封装也未统一拒绝 exceptionDetails。
- `one-in-eight-billion/scripts/e2e-smoke.mjs:47–127`：运行完整交互直到终点，并检查终点区块；连接封装仍有固定端口、任意页面回退和未设命令超时等局限。
- `one-in-eight-billion/scripts/assert-quality.mjs:38–88`：收集空弹窗、超长正文、占位文本及终点问题，并硬失败；其中某类交互的计数只统计而未断言，不能据注释宣称两类都覆盖。

## 已知限制与改进边界

目标页精确绑定、统一参数、连接清理、条件等待、双向结构比较、覆盖矩阵、种子记录及上述更严格的发布门槛，是本次整理提出的约束，不代表源脚本已全部实现。源聚合脚本报告脏文件数却仍标 OK，远程同步判断依赖已有本地引用；因此本流程明确要求分项报告及先更新引用。

本次仅静态审查上述脚本并校验本 skill 的文档结构与链接，未运行源应用、测试套件或浏览器探针。即使将来执行自动化断言通过，也不能推出完整视觉效果、所有随机路径、生产安全或业务效果已经验证。
