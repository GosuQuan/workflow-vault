# 课件诊断与分步揭示

## 适用范围

用户需要修复课件文字可读性，或让例题步骤、答案按点击顺序显示时使用。输入为用户授权处理的 PPTX、目标页范围、期望显示顺序；输出为独立修复副本和检查报告。先使用运行环境已有的 Office/PPTX 技能与工具。

本 skill 提炼操作方法，不包含修复程序。适用于可识别形状的教学模板；不能仅凭某个颜色值就判定该形状一定是答案。

## 执行步骤

1. **建立基线**：记录源文件摘要、页数、目标页及已有动画；输出写入新目录。保留原件，不在导入模块时自动改文件。若必须备份，保留相对目录以避免同名课件互相覆盖。
2. **定位问题**：检查文本 run 的显式颜色、段落默认样式、形状样式、版式、母版和主题颜色。没有显式颜色不等于白字；主题色也不能直接当成固定 RGB。对继承关系无法确定的文本标记为待人工检查。
3. **确认修复范围**：列出目标页、形状 ID、问题类型及建议。显式浅底白字可作为候选；背景图片、透明填充、渐变、表格和组合形状需要单独检查。不要把一个模板的亮度阈值当成普适对比度判据。
4. **最小修改**：仅在确认的目标上设置文字样式，保留字体、字号、上下标和其他结构。图形背景、主题及未选中页面保持原样。诊断报告只需记录页码与形状 ID，避免公开课件原文。
5. **添加分步揭示**：明确每个点击动作对应的形状 ID，例如步骤→答案。ID 必须存在于当前页面。检查已有 timing；默认保留已有动画，不覆盖整个时间线。已有动画与新增顺序冲突时，先提出具体调整方案。
6. **保存副本**：若操作 OOXML，保留 ZIP 中未修改的部件、关系及内容类型；在临时文件中完成修改，验证后再发布副本。避免以 python-pptx 重新保存来代替对不支持动画结构的核验。
7. **分层验收**：按照下述标准报告结果，明确哪些只完成了静态检查。

## 验收标准

- 文件层：ZIP 完整、XML 可解析、PPTX 可重新打开，页数与预期一致。
- 结构层：所有动画目标存在，时间节点 ID 不重复。对自行添加的特定动画模板检查可见性设置与效果配对；不要要求任意原有动画都符合该模板的计数规则。
- 内容层：预期文字、图片与公式仍存在，没有因修复遗漏内容；注意表格和组合形状。
- 视觉层：抽检修改页的实际渲染，确认文字可读、无遮挡、无溢出。静态渲染不能验证点击顺序。
- 播放层：在目标演示软件中实际检查步骤/答案的初始可见性、点击顺序和重复播放。未做播放测试时明确写“动画仅通过结构检查，播放效果未验证”。

## 输出报告

报告修改文件、页码、形状 ID、修改原因、静态检查结果、渲染结果、播放结果，以及未解决事项。修复失败时保留原件与诊断记录，不把部分成功表述成全部通过。

## 提炼来源与限制

提炼自课程工作区的颜色继承检查、批量颜色修复和动画目标验证脚本。原实现依赖固定主题色、固定路径与模板布局；此处将这些假设改为需要验证的输入条件。流程说明本身不代表已对任意 PPTX 验证有效。
