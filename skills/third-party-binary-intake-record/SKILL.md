# 第三方二进制取用与校验归档

## 适用条件

适用于从发布页、应用商店或镜像下载安装包、压缩包、模型权重等二进制，并需要日后复现来源与完整性核对的场景。输入为官方来源地址、版本或标签、下载渠道和本地保存位置；输出为校验记录（来源、文件名、版本、摘要、获取方式、日期、核对结论）。此 skill 只说明取用与记录流程，不提供下载脚本，也不判断软件安全性与合规授权。

## 依赖与参数

记录需要能计算摘要的本地工具和下载渠道；把目标目录、允许来源域名、预期版本、摘要算法和记录文件名放在参数或配置中。默认使用 SHA-256；不要沿用示例中的具体摘要、版本号或项目名作为固定值。二进制保存在仓库之外，记录中不写本机绝对路径、账号、cookie 或带签名的下载链接。

## 执行步骤

1. **确认来源与授权**：优先使用项目官方发布页、官方应用商店或发行版仓库，记录页面 URL、版本号、发布日期与发布日期对应的构建标识。第三方转载、网盘分流和来源不明的镜像不作为校验基准；开源许可或使用条款不允许再分发时，只保留本地校验记录。
2. **下载后立即计算摘要**：对保存到本地的文件计算摘要，算法和大小一并记录。下载中断、文件被替换或工具输出被截断时重新获取，不能用上次结果替代。
3. **与发布方独立核对**：优先比对发布页或官方校验文件中的摘要；上游只提供签名或校验清单时，按该渠道核对。核对渠道与下载渠道不同才有独立价值；同一镜像同时提供文件和摘要只能说明两者自洽。记录每个文件实际使用的对照渠道，未提供摘要的标记为未核对。
4. **按文件逐项记录**：每条至少包含文件名、版本、大小、摘要、来源 URL（或可复核的来源标识）、获取日期、核对渠道和结论。一个版本对应一个明确文件，避免只记录“某软件已下载”。摘要与上游不一致、大小异常或版本不符时保留原文件，标注失败原因并不使用。
5. **放入受控位置**：二进制以配置的下载目录保存，仓库只保留不含摘要之外个人信息的记录文本；图片、截图和安装包本身不入库。若记录需要公开，去掉本机路径、内网地址和账号信息，只保留可公开复核的来源。
6. **更新与失效处理**：新版本发布后新增记录而不是覆盖旧记录，注明旧版本是否仍可获取；上游撤销版本或发布更正时在记录中标注时间与影响。定期抽检已保存文件摘要，发现变化时按失败处理并重新获取。
7. **区分校验与安全判断**：摘要一致只说明文件与发布方声明一致，不代表二进制不含恶意代码、符合平台政策或许可要求。安装前仍需按组织规则做安全审查；无法完成审查时记录未评估，不据来源可信推定安全。

## 验收标准

- 每个文件都有可复核的来源、版本、大小、摘要和对照渠道，摘要算法明确。
- 摘要比对结论分为一致、未核对、不一致三类，未核对不写作通过。
- 仓库中没有二进制、安装包、截图或含个人路径的校验记录。
- 新旧版本记录可追溯，失败或撤销的版本保留原因且未被继续使用。

## 提炼来源与改进边界

源自源工作区 `teleprompter-apk/SHA256SUMS.txt` 的下载校验记录做法：对三个开源安卓安装包计算 SHA-256，并分别与 GitHub 发布页和 F-Droid 官方来源对照，二进制本身留在本地目录。

该记录是一份具体文件的清单，不是通用流程：它只记录单一时间点的摘要与来源，没有版本历史、抽检复核、失败分类或安全评估，也不含可复用的下载与校验脚本。本 skill 中的受控位置、三类结论、逐项来源、更新与失效处理、安全判断边界，均为整理后的建议，不代表源记录已实现或验证。此次仅静态阅读该文本记录与目录结构，未重新下载文件、未复算摘要、未运行或安装任何安装包。
