# 每日沉淀 SOP

每天早上把工作区里新出现（或被改进）的、值得复用的工作流与 skill 收进本仓库。

## 1. 找增量

- 源目录默认使用任务宿主的当前默认工作区，目标目录由任务配置提供，不在公开文档中固化个人路径。若源根目录不是 Git 仓库，枚举其中的独立仓库，分别检查提交、未提交修改和未跟踪文件；Git 之外的自有文件仍需扫描。
- 从目标仓库 Git 私有目录下 `daily-distill/state.json` 的 `last_successful_check_at` 开始检查，延迟执行补扫整个空档。通过 `git rev-parse --absolute-git-dir` 定位 Git 私有目录（兼容 worktree）；无记录、源根目录改变或记录损坏时全量建立基线，不把最新归档提交时间视作源目录检查时间。
- Git 提交同时参考上次记录的 HEAD 与时间范围；HEAD 不再是当前分支祖先时核对分支/历史变化并扩大扫描，不能仅按提交日期跳过内容。
- 同时检查未提交、未跟踪文件，并与已归档版本比较；提交历史不包含尚未提交的工作。修改时间只用于筛选，必要时用内容摘要确认是否变化。
- 关注三类：**可复用工具**（脚本/服务）、**可复用流程**（做法/约定）、**可复用提示词与 skill**。

## 2. 判断是否值得收

- 通用性：换个课题/课程还能用吗？硬编码的个人路径、业务数据要能参数化或删掉。
- 复用频率：一次性脚本体量小可以不收，但把它的"做法"沉淀成文档。

## 3. 脱敏与版权检查（硬性，逐条过）

- 无密钥：对候选文件 grep `api key / token / secret / password / Authorization / Bearer`。
- 无第三方版权内容：真题原文、课件截图、歌词曲谱等一律不收（工具本身可以，素材不行）。
- 无个人数据，无大二进制（PDF/图片/zip 不入库）。

## 4. 归档

- 新工具 → 新建目录 + README（用途/用法/依赖/注意），必要时把硬编码路径改成 argv 参数。
- 同类增强 → 并入现有目录，更新其 README 与根 README 的目录表。
- 纯流程/约定 → 写进 `docs/`。
- 更新根 README 的目录表。

## 5. 提交与发布

- 用 `git add -- <已审查文件列表>` 精确暂存，检查 `git diff --cached --stat` 与 `git diff --cached --check`；不要把用户的其他修改一起发布。
- 提交中文一句话信息并 push 到 `origin main`，检查退出码和分支状态；遇远程分歧先核对，不强制覆盖。
- 无合格增量时不制造空提交，汇报检查范围和跳过原因。
- 推送失败：保留本地提交，下次先核对并补推。
- 扫描开始时保存候选清单和 SHA-256，检查结束前复核待发布内容的摘要。`state.json` 保存源根目录、扫描起止时间、各源仓库 HEAD、源文件摘要、归档映射与摘要、跳过原因、本地提交和发布状态；本机清单、个人路径及原始数据只放 Git 私有目录，不提交。
- 完成全部审查、验证和发布后，原子更新 `last_successful_check_at`；水位取扫描开始时间，以便下次重叠补扫执行期间的变化，摘要负责去重。无合格增量且检查完整时，也可更新本地水位，不为时间记录制造提交。
- 有失败、未审候选或推送失败时，保留待处理记录，不推进成功水位。下次先核对本地提交与远程状态再补推，确认提交已在远程后完成记录；丢失本地状态时全量补查。
- 汇报本次检查起止时间、覆盖水位、发布提交号（若有）及未解决事项。文档中的能力说明区分原源码能力、整理建议与本次实际运行的验证。

## 6. 汇报

- 新增/更新了什么、放在哪、为什么值得收；跳过了什么、为什么。
